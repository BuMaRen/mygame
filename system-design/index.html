系统设计

分两部分：先对单个理论和设计方法做专项训练，再结合真实业务场景做完整设计。

练习顺序

每周练 2 个场景，间隔几天复述一次。每道题下方列出了建议先在第一部分练好的知识点。

5 分钟澄清需求 → 10 分钟画组件与数据流 → 10 分钟解释关键决策 → 5–10 分钟答追问。先回答题目本身；遇到项目事实不确定时再回到文档核对。

第一次答题？展开通用答题格式
  1. 澄清范围：谁使用、做什么、哪些需求暂不覆盖；明确成功标准。
  2. 估算规模：请求量、数据量、时延或吞吐目标，说明估算依据。
  3. 接口与数据：主要 API / 事件、核心实体、状态变化和数据归属。
  4. 架构与主流程：画组件图，沿一条请求讲清读写、同步与异步边界。
  5. 异常与一致性：超时、重试、重复请求、节点故障如何处理；说明哪些结果需要强一致。
  6. 运行与安全：监控告警、扩容、限流、权限与敏感数据（按题目取舍）。
  7. 取舍与演进：说出为何选这个方案、代价、当前瓶颈和下一步优化。
  8. 追问：针对面试官改变的约束，修改图和方案。
