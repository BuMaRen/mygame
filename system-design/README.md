# 系统设计

分两部分练，页面顶部切换。

## 第一部分：理论与方法

对单个理论或设计方法做专项训练，共 28 个知识点，按估算与接口、扩展与负载、缓存、数据与一致性、异步与消息、可靠性与稳定性、安全与运维分组。每个知识点标了重要程度：

- **★ 核心**（15 个）：几乎每场系统设计面试都会用到，列表里高亮，优先练；
- **常见**：核心练完后再练；
- **进阶**：后期再练。

每个知识点的练法：AI 生成讲解（是什么、怎么工作、何时用、取舍、误区、常见追问）→ AI 出一组 4–5 道小题（概念、原理、应用、取舍、陷阱）→ 作答后 AI 逐题评估并给参考答案和评分要点。达到 80 分算掌握；没到就再出一组新题，新题会避开做过的角度，并针对上次暴露的误解。知识点清单在 `content/concepts.js`，记录保存在 `data/concepts.json`。

## 第二部分：业务场景设计

结合真实业务需求做完整设计。先练与 CaseHub、auto-test 有交集的六个通用设计问题：异步任务、中断、重复请求、变化中的知识、AI 产物上线和端到端质量工程。前五个主题使用其他业务场景来练迁移能力，第六个可以直接用项目。之后练数据、业务事件、热门内容、突发流量、故障排查和多租户等通用题。每周练两个场景。每道题下方列出建议先在第一部分练好的知识点，可点过去。点击“AI 生成系统设计题”会调用本地 CLI；前六个主题还会读取相邻仓库文档作为设计背景。题干只给业务背景、需求和客观条件，不预设架构或技术方案。


每次练习先澄清需求，再用页面上的组件和连线画架构图，按[答题格式参考](answer-guide.html)写下规模、接口、数据、主流程、故障处理和取舍，逐项回答追问。页面自动保存方案和图；“AI 评估方案”会给出评分、具体缺口、追问反馈和下一次练习方向。评估只基于写入页面的内容；口头解释也应简要记下，避免凭空被评分。复盘记录保存在 `data/progress.json`。

CLI 配置见根目录 [README](../README.md)。本地仓库文档只为前六个主题提供设计灵感；AI 的项目事实和改造建议仍需回到代码或文档核对。

如果已生成的题目直接给出解决方案，可点“换一道题”。旧题目和已写的方案会保存在当前主题的历史记录中；新题生成失败时原题不会被替换。
